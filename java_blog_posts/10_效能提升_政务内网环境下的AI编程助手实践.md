# 效能提升：政务内网环境下的 AI 编程助手实践

## 背景
“互联网 + 政务”项目开发中，最大的痛点是**物理隔离**。
开发环境在内网，无法访问 Github Copilot，也禁止将代码片段上传到云端（ChatGPT）。
但这并不意味着我们必须退回到刀耕火种的时代。本文分享如何在**断网、保密**的前提下，在政务项目中落地 AI 编程助手。

## 1. 痛点与红线
*   **红线**：代码绝对不能出内网。任何基于 Cloud 的 AI 插件（Copilot, CodeWhisperer）都严禁使用。
*   **痛点**：内网查资料难、写重复代码效率低、依赖库文档缺失。

## 2. 解决方案：私有化部署代码大模型

### 2.1 模型选型
我们需要一个专精于代码生成、且参数量适中（能跑在单张消费级显卡上）的模型。
*   **CodeGeex4-All-9B (智谱AI)**: 国产最强代码模型之一，支持 9B 参数，单卡 3090/4090 即可流畅运行。对中文注释理解极佳。
*   **DeepSeek-Coder-V2-Lite**: 深度求索的代码模型，逻辑推理能力强，且开源协议友好。
*   **StarCoder2**: 也是不错的选择，但中文支持稍弱。

### 2.2 部署工具：Ollama + Continue
**Continue** 是目前最强大的开源 AI 编程插件（支持 VS Code 和 JetBrains），它最大的特点是**支持连接本地 Ollama**。

**架构图**：
`内网开发机(VS Code + Continue插件)` <--> `内网推理服务器(Ollama + CodeGeex)`

**操作步骤**：
1.  在内网推理服务器安装 Ollama 并运行模型：`ollama run codegeex4`。
2.  在开发机 VS Code 安装 Continue 插件（需离线安装 vsix 包）。
3.  配置 Continue 的 `config.json`：
    ```json
    {
      "models": [
        {
          "title": "CodeGeex-Intranet",
          "provider": "ollama",
          "model": "codegeex4",
          "apiBase": "http://192.168.1.100:11434"
        }
      ],
      "tabAutocompleteModel": {
        "title": "StarCoder-Local",
        "provider": "ollama",
        "model": "starcoder2:3b", 
        "apiBase": "http://192.168.1.100:11434"
      }
    }
    ```
    *技巧*：自动补全（Autocomplete）建议用更小的模型（如 3B），响应更快；对话（Chat）用大模型（9B+）。

## 3. 实战场景

### 3.1 遗留代码解释
政务系统常有十几年前的“祖传代码”（如老旧的 JSP、Struts2）。
选中代码，按 `Ctrl+L`，问本地 AI：“这段代码的业务逻辑是什么？有什么潜在的安全漏洞？”
DeepSeek/CodeGeex 能精准识别 SQL 注入风险，并给出修复建议。

### 3.2 快速生成 SQL 与实体类
输入：“创建一个公务员信息表，包含姓名、职务、入职时间，并生成对应的 JPA Entity。”
AI 直接生成符合国标字段定义的 DDL 和 Java 代码。

### 3.3 离线文档检索
Continue 支持 `@Docs` 功能。我们可以将内部的开发规范 PDF、私有 SDK 文档建立索引。
写代码时，AI 会参考这些内部文档进行补全，确保代码符合《XX厅开发规范》。

## 4. 安全合规管控
为了让领导放心，我们在实施时做了以下管控：
1.  **网络限制**：推理服务器通过防火墙策略，仅开放 11434 端口给开发网段，严禁访问外网。
2.  **审计日志**：使用 Nginx 反向代理 Ollama，记录所有请求日志，确保可追溯。
3.  **模型微调 (可选)**：如果有大量内部框架代码，可以使用 LLaMA-Factory 对模型进行 LoRA 微调，让 AI 更懂内部框架。

## 总结
在政务内网环境中，通过 **Ollama + Continue + 国产代码模型**，我们完全可以构建一套媲美 Copilot 的编码体验。
这不仅是效率的提升，更是**数据安全**与**技术创新**的最佳平衡点。
